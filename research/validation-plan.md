# PoC 验证与验收计划

## P0：LiteLLM 协议兼容

**环境**：隔离 VM / 容器；只接测试上游和测试密钥。

1. 记录 TokenRouter 基线版本与测试用例。
2. 测试标准请求、流式输出、tool_calls、图片/多模态（仅在上游支持时）。
3. 验证 OpenAI 与 Anthropic 协议的 role/usage/错误映射。
4. 注入 401/403、429、5xx、超时、断流。
5. 比较额外代理开销、路由与重试行为。

**通过条件**：请求返回正确、错误类别可解释、流式完整、个人用量无漏记或重复记账。并非仅凭 HTTP 200 即通过。

## P0：Langfuse 追踪

1. 只发送人工构造/脱敏测试数据。
2. 记录一次完整 Agent 多步骤 Trace。
3. 对比网关日志中的 request_id、模型、耗时、Token。
4. 验证隐私开关、存储位置及故障旁路降级。

**通过条件**：能定位失败节点与耗时；日志脱敏；观测服务中断不影响主请求。

## P1：RAGFlow 解析与检索

1. 10 份脱敏样本：PDF/Word/Excel/扫描件/复杂表格。
2. 对照现有智脑解析、检索、引用、回答流程。
3. 记录表格单元格准确率、召回与引用、首字延迟、CPU/内存。
4. 比对许可证和服务依赖。

**通过条件**：按业务权重的总体效果明显提升且不破坏现有知识权限边界；具体阈值由业务/研发在测试前定。

## 后续顺序

- vLLM：4090D、5090 硬件实测，确认当前 CUDA/驱动与模型版本。
- Dify/n8n：验证业务工作流，但只用测试数据和测试接口。
- OpenHands：最小权限沙箱与只读代码测试；写入操作必须另行授权。
- New API/One API/Open WebUI：产品对标文档，不直接生产集成。
